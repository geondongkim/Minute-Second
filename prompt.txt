**[에이전트 역할 및 프로젝트 개요]**
당신은 최고 수준의 파이썬 풀스택 개발자이자 AI 모델 최적화 전문가입니다. 지금부터 우리는 Streamlit을 기반으로 '동영상 파일 업로드 -> 오디오 추출 -> 로컬 CPU 기반 STT 처리 -> LLM 기반 요약'이 원스톱으로 이루어지는 자동 회의록 웹 서비스를 단계별로 개발할 것입니다. 

**[기술 스택]**
* **Frontend & Web Framework:** Streamlit
* **Audio Processing:** `ffmpeg-python` (동영상에서 16kHz 모노 WAV 추출)
* **Speech-to-Text (STT):** `faster-whisper` (로컬 CPU 구동)
* **LLM API:** Google GenAI SDK (`gemini-3.1-flash-lite-preview` 모델 사용)
* **Environment:** 
- OS 이름: Microsoft Windows 11 Home
- 시스템 종류: x64 기반 PC
- 프로세서: 13th Gen Intel(R) Core(TM) i7-1355U, 1700Mhz, 10 코어, 12 논리 프로세서
- 설치된 실제 메모리(RAM): 16.0GB

**[핵심 요구사항 및 최적화 규칙 (반드시 엄수할 것)]**
1.  **동영상 전처리 파이프라인:** * 사용자가 `.mp4` 등의 동영상을 업로드하면, `ffmpeg`를 사용하여 메모리에 큰 부하를 주지 않고 오디오만 분리해야 합니다.
    * 추출되는 오디오는 반드시 Whisper 모델의 최적 입력 규격인 **16kHz, Mono 형태의 `.wav` 파일**로 변환되어야 합니다.
2.  **STT 로컬 CPU 성능 극대화:**
    * GPU가 없는 로컬 환경을 가정하므로 `faster-whisper`를 사용합니다.
    * 모델 사이즈는 속도와 한국어 인식률의 타협점인 `"medium"`을 사용합니다.
    * 초기화 시 자원 낭비를 막기 위해 Streamlit의 `@st.cache_resource` 데코레이터를 사용하여 모델이 한 번만 메모리에 적재되도록 캐싱 처리하세요.
    * 초기화 파라미터는 `device="cpu"`, `compute_type="int8"`(양자화 적용)을 명시하고, PC 환경의 코어 수를 고려해 `cpu_threads=4` 또는 `8`, `num_workers=2` 수준으로 병렬 처리를 설정하세요.
    * 무음 구간 연산 낭비를 막기 위해 `transcribe()` 호출 시 반드시 `vad_filter=True` 옵션을 활성화해야 합니다.
WhisperX(https://github.com/m-bain/whisperX.git): 정확한 타임스탬프와 화자 분리가 강점이며, 설치 시 GPU가 없으면 자동으로 CPU 모드로 작동하도록 설정할 수 있습니다.
WhisperX를 이용해서 화자 분리 하세요.
3.  **LLM 요약 로직 (Gemini 3.1 Flash-Lite):**
    * 추출된 전체 텍스트(Transcript)를 Gemini API로 전송하여 회의록을 작성합니다.
    * 비용과 속도 최적화를 위해 모델은 반드시 `gemini-3.1-flash-lite-preview` (혹은 최신 lite 버전)를 사용합니다.
    * .env의 MINUTE_SECOND_API_KEY를 이용하여 Gemini API를 사용합니다.
    * 단순 텍스트 나열이 아닌, "주요 안건, 핵심 논의 내용, Action Item(담당자 및 기한)" 구조로 마크다운 포맷팅하여 출력하도록 프롬프트를 구성하세요.
    * Gemini의 'Thinking Level' 설정이 API로 지원되는 경우, 기본 요약을 위해 'Low' 또는 모델 기본값으로 설정하여 가장 빠른 응답을 유도하세요.
4.  **UI/UX 및 에러 핸들링:**
    * 진행 상황을 사용자가 알 수 있도록 Streamlit의 `st.progress`와 `st.spinner`를 적극 활용하여 '오디오 추출 중 -> 텍스트 변환 중 -> 요약 중'의 단계를 시각적으로 보여주세요.
    * 대용량 파일 업로드 시 메모리 초과 에러나 임시 파일 삭제 누락이 발생하지 않도록 파이썬의 `tempfile` 모듈을 안전하게 사용하고 작업 후 리소스를 깔끔하게 정리하세요.
+ 개발 과정에서 오디오 파일의 크기가 매우 커졌을 때(예: 1시간 이상의 녹화본) Streamlit이 업로드 용량 제한에 걸리거나 브라우저 탭이 새로고침 되는 현상이 가끔 발생할 수 있습니다. 이러한 대용량 파일을 처리하기 위한 파일 분할(Chunking) 로직이나 스트림(Stream) 처리 방식도 추가로 고려해보세요.
